# 帧语智能编辑器 WebAV Demo

**首次使用请先看 [Windows 完整操作说明](docs/OPERATION-GUIDE.zh-CN.md)**：下载与安装 → 启动 → Studio/Editor 区别 → Mock 演示 → 导出 → 真实 API 配置 → 故障排查。

本版保留两个独立编辑入口，不合并界面；当前工程不在两个页面之间同步。

浏览器本地视频编辑 Demo：导入多个 MP4 视频素材，顺序剪辑或加入多个视频轨叠加；再添加 MP3/WAV 背景音乐或音效、手动字幕，在 WebAV 画布预览后导出烧录字幕和混音的 MP4。手动编辑与 Mock 模式在本机处理；真实 AI 模式仅在用户确认后发送有限抽帧和必要描述，不上传完整视频或音频。

## Windows 启动与本次适配

本目录基于 GitHub main 的 64924704ae288aba0e95b8f229e8f19e182152b9，保留其素材抽屉、裁剪性能优化和导出配置，并接入本地首页、Studio 智能剪辑及 Windows 启动器。详细记录见 [适配报告](docs/INTEGRATION-20261021.md)。

1. 安装 Node.js 22.10+（含 npm），在包含 package.json 的目录运行 `npm.cmd ci`。
2. 双击 `start-ai-mock.cmd`，或运行 `npm.cmd run dev:ai:mock`。
3. 在 Chrome / Edge 打开 http://127.0.0.1:5173 ：首页“创作”进入 `/studio`；页脚“原版编辑器”进入保留远程最新功能的 `/editor`。
4. 真实联调按 [Windows AI 启动说明](WINDOWS-AI-启动说明.md) 在本机填写 server/.env 并使用 `start-ai-real.cmd`。本次没有调用付费 API。

如果提示 npm 不存在，双击启动器会寻找已安装的 Node，直接启动已有依赖；首次安装依赖仍需含 npm 的 Node.js。不要同时运行旧目录和新目录的默认服务，二者都占用 5173 / 8787。

以下功能列表主要描述 `/editor`；AI 方案确认、整批撤销在 `/studio`。两者共享工程类型及 WebAV 引擎，未新增第三个演示站点。

## 功能范围

- 固定 1280×720 / 30 FPS / 16:9 导出；非 16:9 视频等比缩放并保留黑边。
- 素材面板顶部采用靠左的窄竖向矩形“素 / 材 / 库”抽屉与“上传视频、上传音乐/音效、添加字幕”三个直接操作入口；标签高度自动与右侧三按钮组对齐，紧凑抽屉可悬停或点击固定并向右滑出，按视频/音乐/音效打开统一素材库弹窗。音频快捷菜单及弹窗入口均在同步用户手势中打开系统文件选择器，复用真实 SHA-256 去重与导入流程。
- 素材列表可按全部、视频、音乐、音效、字幕筛选并独立滚动。音乐/音效会在工程素材数据中保留分类；音频卡片可试听本会话导入的本地文件，字幕卡片引用实际字幕片段。
- 视频、音乐和音效导入均使用“文件大小初筛 + 后台 Worker SHA-256 内容确认”去重；音乐与音效共用音频去重范围，因此跨分类相同内容只保留最初的 Asset。文件名不同但内容相同不会创建第二个 Asset、File 运行时引用或分析缓存。检测到重复会提示并可定位既有素材；同一既有 Asset 仍可多次加入任意时间轴轨道。Chrome/Edge 使用 Worker 执行整文件 WebCrypto 摘要，避免主线程计算阻塞；WebCrypto 原生 API 不提供流式 SHA-256，超大文件仍会在 Worker 中占用完整文件缓冲区。
- 默认提供字幕、视频、背景音乐、音效轨；可新增、重命名、排序、调整高度或删除空轨。可新增多条视频轨：同一视频轨禁止片段重叠，不同视频轨可同时播放并叠加。
- 视频轨按 `Track.order` 从 UI 上到下排序：较小 `order` 表示更靠上，映射到更高 WebAV `zIndex`，因此上方视频轨覆盖下方视频轨；字幕固定在全部视频图层之上。
- 轨道标签列固定在左侧，轨道内容独立纵向滚动；标尺与片段区域横向同步，时间零点始终在标签列右侧 110px。
- 素材库、预览、属性栏以及底部时间轴可拖拽调整尺寸，双击分隔条恢复默认。面板尺寸只保存在当前浏览器会话。
- 同一视频素材可多次引用。工程时长只由视频片段的最晚结束时间决定，音频和字幕不会延长画面。
- 音频/字幕支持 100 ms 吸附移动、左右裁剪；音频裁剪使用 `AudioClip.split`，不是单纯缩短时间轴矩形。
- 可从素材面板手动输入字幕文本、起止时间；右侧可继续编辑字幕文字、样式、位置、时间及音频起点、时长、音量。
- 视频片段可在视频轨内移动、跨视频轨移动、左右裁剪和删除；删除不触发波纹移动。视频裁剪复用 WebAV 的 `MP4Clip.split` 路径，画面与原声始终使用同一源区间。
- 视频属性支持全画面、Fit、Fill、右上角画中画、1280×720 内部坐标位置/尺寸、保持宽高比、透明度及原声音量/静音；可在预览框中拖动选中图层，并通过四角及四边中点八个控制点缩放。Fit（新片段及恢复默认）保留完整画面；Fill 以超出输出画布的 Sprite rect 等比覆盖画布，输出画布外部分由 WebAV 裁去；全画面则将 rect 直接填满 1280×720。三者均不改变原始媒体文件或伪造源裁切。
- 每个视频片段都可保存独立的归一化 `sourceCrop`；缺失该字段的旧工程按完整画面处理。确认裁切后，预览和导出均通过同一 WebAV `tickInterceptor` 实际变换视频帧：优先用 WebCodecs `VideoFrame.visibleRect` 创建轻量裁切视图，不支持时复用 `OffscreenCanvas` 做逐帧回退。进入、取消或确认裁切只重建该视频 Sprite，不会在手柄拖动时反复解码；裁切不改变原声、源时间区间、片段时长或倍速，分割会继承原裁切。真实媒体结果仍须按手工清单在本地 Chrome/Edge 验收。Phase 6.3 阶段 A 的 `?sourceCropPrototype=1` 仍保留为固定中央 50% 开发验证入口，仅供排查。
- 音乐/音效与视频素材进入素材库后即自动排入同一个单并发的 WebAV PCM 波形分析队列；卡片会显示等待、解码、生成、完成、无音轨或失败状态，失败可重试。视频原声使用 `MP4Clip.splitTrack()` 的纯音频轨连续 `tick()`，不解码视频帧；Peak+RMS 包络缓存按“素材类型 + Asset ID”复用，完整 PCM 不写入工程或 React 状态。音乐和音效轨默认采用 DPR-aware Canvas 的**单侧离散竖柱**：RMS 为底部主柱、Peak 为细小瞬态延伸；缩放、轨高、裁剪及倍速仅重新采样缓存，不重新解码。视频轨默认显示由 `MP4Clip.thumbnails()` 生成的连续缩略帧：普通素材缓存每源秒一张，长素材最多 180 张；每个片段按时间轴每秒取一张，并按 `sourceStartMs`、源时长与倍速映射对应源时间。视频原声波形分析不再占用视频轨视觉层。以上均只影响显示，不影响片段音量、预览音频或 MP4 导出。
- 顶栏“导出视频”会打开配置面板：可编辑文件名、明确显示唯一可靠格式 MP4（H.264/AAC），并选择浏览器下载或 Chrome/Edge 的系统另存为。文件选择器在点击“开始导出”的用户手势内打开；取消选择不会启动编码。其他容器格式没有伪造支持。
- 波形诊断面板提供“Canvas 自检”：它使用确定的合成包络、无需 WebCodecs，可用来区分 Canvas 布局/绘制故障与真实媒体分析故障。缓存完成日志包含缓存键、版本、桶数、Peak/RMS 统计和非零桶数量。
- “+ 音乐 / + 音效”与波形分析完全解耦：单击立即创建一个工程片段，可在首条视频导入前暂存；视频加入后再按视频项目时长应用常规边界。每次点击均有 `[TimelineAdd]` 控制台追踪，缺少对应轨道会显示错误而非静默失败。
- 选中视频、背景音乐或音效片段后，可将播放头置于片段内部，通过工具栏“分割”、右键菜单或非输入焦点下的 `S` 分割。左右片段拥有独立 ID、保持原轨道/素材/音量/视频布局；字幕不支持分割。
- 视频、背景音乐和音效片段支持 0.5×、0.75×、1×、1.25×、1.5×、2×。工程时长与源媒体截取时长分别保存；变速保留源区间并重算时间轴占用长度。同轨视频减速若会重叠会被拒绝。WebAV 1.2.8 使用线性插值处理音频变速，音调会随速度改变。
- 当前不包含转场、遮罩、色度抠图、关键帧动画、语音识别、FFmpeg 或云端保存。/editor 无撤销重做；/studio 支持会话内撤销重做及整批 AI 计划撤销。编辑器主要面向桌面窗口。

## 架构

- `src/editor`：工程数据、编辑命令与时间计算；内部时间统一为毫秒。
- `src/editor/layoutMath.ts`：工作台最小尺寸与窗口收缩时的尺寸校正。
- `src/webav/WebAVAdapter.ts`：本地 `File` 与 WebAV 运行时对象的隔离、画布预览、音频切片、字幕位图和 MP4 输出；仅在这一层转换微秒。
- `src/App.tsx`：工作台、素材导入、属性面板和自定义轻量时间轴。连续拖拽会节流同步至 WebAV，导出前总是根据最新工程快照重建合成器。
- `src/timeline/WaveformCanvas.tsx`：按设备像素比和当前可见片段宽度聚合 Peak+RMS，绘制不拦截指针事件的底部离散竖柱波形。

## 手工验证清单

1. 连续导入两个内容明显不同的 MP4；确认第二个只进入素材库，点击其“+ 视频轨”后，两个片段在同一视频轨首尾相接，且总时长等于两者之和。
2. 将片段 B 拖到片段 A 后方留出空隙，播放或跳转至拼接边界，确认片段 A 后出现片段 B、各自原声同步；空白区间应为黑色而非残帧。将 B 拖到 A 上方或将 A 的右边缘拖入 B，应被拒绝而不会产生重叠。
3. 拖动视频片段的左右白色边缘：右裁剪只改变使用时长；左裁剪同时改变工程起点与源文件起点。确认在预览及导出中画面和原声都来自裁剪后的同一段源视频；删除其中一个片段后，另一个仍停留在原时间位置并可播放。
4. 新建第二视频轨，将视频 B 加入该轨并设为 2 秒开始；选择 B 后点击“画中画”，确认 0～2 秒仅有 A，2 秒后 B 位于右上角。拖动 B 的预览边框和右下角手柄，或修改 X/Y/宽高/透明度，确认预览立即变化且重新跳转后保持一致。
5. 将两个视频轨上下排序，确认较后视频轨覆盖较前视频轨；把 B 跨轨移动，确认素材源区间、画面布局和时间保持。尝试在同一视频轨重叠两个片段，应被拒绝。
6. 分别修改 A、B 原声音量并将一条静音；叠加背景音乐、音效和字幕后试听。导出的 MP4 应保留正确的画面层级、两条视频原声混音、外部音频和字幕。
7. 在音乐、音效轨添加 MP3/WAV，确认片段内出现真实波形；静音段接近零，高振幅段较高。左右裁剪后，波形应切换到相应的源音频区间；缩放、改变轨高、纵向滚动与拖拽操作都不应使波形遮挡手柄。
8. 在视频片段中确认连续缩略帧默认按时间轴每秒一张显示；同一视频的不同裁剪、分割、跨视频轨移动、静音及倍速片段应显示正确源区间。2× 片段每个时间轴秒应推进两个源秒，0.5× 则推进半个源秒。无音轨视频仍可正常编辑。
9. 拖动三条工作区分隔条，双击分别复位；缩放中央区时确认预览画布等比显示，视频实际输出尺寸仍为 1280×720。
10. 检查素材面板顶部五个入口在滚动素材列表时保持不动；切换全部/视频/音乐/音效/字幕筛选，确认列表独立滚动。导入音乐、音效后确认分类色彩、试听和相应添加按钮正常；“生成待接入”不得产生伪造结果。
11. 通过“导入/生成字幕”输入文字与起止毫秒，创建后确认字幕卡片、时间轴、右侧属性与画布使用同一真实字幕片段。
12. 新增 10 条以上字幕/音乐/音效轨，调整部分轨高并上下滚动；确认标签、片段、网格和播放头仍对齐，横向滚动不影响纵向位置。
13. 新增两条背景音乐轨和两条字幕轨；将片段拖到同类型轨，确认时间、素材及字幕样式不变。预览和导出应同时包含所有音频、字幕片段。
14. 导入 MP3 和 WAV，分别添加为背景音乐与音效，移动到不同时间位置并确认可叠加播放。
15. 添加字幕，编辑文字、颜色、字号、位置和时长，确认预览与时间轴同步。
16. 右、左裁剪音频后确认听到的音频源内容确实改变；调整音量后确认预览变化。
17. 选中视频、背景音乐或音效片段，将播放头置于中间，分别用工具栏“分割”、右键“在播放头处分割”和键盘 `S` 分割。确认分割前后源内容连续、两个片段可独立移动/裁剪/删除；聚焦任何输入框后按 `S` 不得触发分割；字幕片段和片段边缘处不得分割。
18. 对右上角画中画视频执行分割，确认两段都继承位置、尺寸、透明度、静音与原声音量；检查对应缩略图/波形分别反映正确源区间。
19. 对 10 秒视频分别选择 2×（时间轴应为约 5 秒）和 0.5×（约 20 秒），确认播放头、片段宽度、总工程时长与预览都一致；在 2× 片段工程第 2 秒处分割，检查右片段从源第 4 秒开始。反复切换 1×、2×、0.5×、1×，确认时长不累积漂移。
20. 将一条视频设为 2×、另一条保持 1×并设为画中画；确认各自画面/原声同步、图层位置/透明度不变。分别对背景音乐、音效设定速度、左右裁剪并叠加字幕，确认波形/缩略图对应源区间。导出后重新播放 `frameyu-demo.mp4`：检查多轨画面、原声、外部音频、字幕和速度都与预览一致；音频音调变化属于当前 WebAV 算法的预期限制。
21. 导入约 10 秒 MP3、30～60 秒 WAV、约 3 分钟 MP3；在素材卡片确认“等待分析 → 正在解码 → 正在生成波形 → 波形分析完成”状态。展开“波形诊断日志”并复制 JSON，记录 `readyMs`、`peakBuildMs`、`totalMs`。连续导入三条音频，确认同一时刻仅一条处于解码/生成状态；把同一素材多次加入轨道，确认日志没有第二次解码。对故意无法解码的文件检查失败原因和“重新分析”。
22. 导入一条有明显原声的 MP4、一条无音轨 MP4 和一条静音 MP4。确认素材卡分别显示完成、无音轨、完成；有声视频时间轴上半为缩略图、下半为波形，静音视频波形接近零，无音轨仅显示缩略图。对有声视频进行左右裁剪、分割、跨轨移动、静音及 0.5×/2× 变速：波形应按源区间采样、随时间轴宽度变化，静音不应移除原始波形。展开诊断日志，记录 `trackSplitMs`、`audioTickMs`、`totalMs`；导出后确认没有额外声音或原声重复。
23. 用同一条 `webav-44.1kHz-2chan.mp3` 依次在 45、100、240 时间轴缩放倍率及低/高轨道高度观察波形：它应为中线对称的连续填充包络，静音处为零、弱音仍有可辨高度、强弱顺序稳定。分别切换“线性/增强”，记录增益、对比度；增强模式下低电平细节应更清晰，但静音仍为空白，恒定振幅不得被伪造成峰谷。展开诊断日志并复制 `envelope-summary` 与 `[WaveformCanvas] painted` 的 `P10/P50/P90/P95/P99`、`effectiveHeight`、`maxPeakHeight`；对同一素材截取的两个片段应具有相同参考比例。分割、左右裁剪和同源多次引用后，各段必须显示同一源区间的细节且不得重新触发解码。分别检查音效琥珀色、音乐青绿色和视频原声浅蓝色，并保存线性/增强各一张截图以便比较。
24. 展开“波形诊断日志”，点击“显示 Canvas 自检”。不导入任何素材时也应看到明显起伏、带静音缺口的青绿色波形；控制台应输出一次 `[WaveformCanvas] painted`，其中 CSS 尺寸、像素尺寸、桶数和最大振幅均为正值。若自检可见而真实素材不可见，请复制 `envelope-summary` 与 `painted` 日志。
25. 导入三个画面颜色明显不同的视频并在同一时间置于三条视频轨。时间轴更靠上的视频轨必须覆盖下方轨；拖动底部轨到最上方后，预览画面遮挡关系应立即翻转。导出 MP4 后图层关系必须与预览一致，字幕仍应位于最上层。
26. 选中一个视频片段，验证预览框的八个控制点：四角保持比例缩放，四边中点在比例锁定时以中心为基准调整另一维；取消“保持宽高比”后可独立调整宽/高。拖动框内区域移动图层，再依次点击 Fit、Fill、全画面、画中画、恢复默认；属性面板的 X/Y/宽/高/透明度必须与画布结果一致。调整工作台面板尺寸后，控制点仍应与画面边界对齐。对画中画执行分割、跨轨移动及变速，确认布局仍被保留。
27. 导入一个短 MP4 后，用文件系统复制出同内容、不同文件名的副本并再次导入：应显示“检测到重复素材”对话框，点击“定位已有素材”应切换到视频筛选并定位原卡片；素材总数、运行时预览和已有时间轴片段都不变。使用同名但内容不同的 MP4 时应允许导入。连续快速选择同一个文件两次时也只能出现一个素材卡片。将既有素材重复点击“+ 视频轨”应仍创建多个独立时间轴片段。
28. **Phase 6.3 阶段 A（本地 Chrome/Edge）**：准备一个带声、画面中央与边缘内容明显不同的 1280×720 H.264/AAC MP4。在 `http://localhost:5173/?sourceCropPrototype=1` 导入并播放，应看到预览只保留并放大源画面中央 50%，左/右/上/下边缘内容均不可见；页面左上会显示“裁切原型”提示，控制台有 `[SourceCropPrototype] installed`。导出 MP4 后重新播放，裁切内容必须与预览一致，原声、时长、倍速与其他音轨不应改变。再关闭查询参数刷新，确认完整源画面恢复。远程无头 Chromium 缺少 WebCodecs，不能替代此验收。
29. **Phase 6.3 正式裁切（本地 Chrome/Edge）**：不带查询参数导入视频、选中时间轴视频片段，在右侧点击“裁切”。确认预览显示完整源画面、选区外有遮罩，八个手柄与内部拖动均不越界；分别选择自由、16:9、9:16、1:1、4:3 并拖动手柄。点击“取消”应恢复旧裁切，点击“重置裁切”应恢复完整画面，点击“确认”后重新跳转/播放应看到真实裁切结果。将两个视频叠加、分别裁切并设其中一个为画中画；再对裁切视频分割、变速、跨轨移动，确认两段继承裁切且另一视频不受影响。最后导出 MP4，重新播放确认预览与成片的裁切画面、层级和原声一致。

详细 API 和阶段测试记录见 [`docs/verification.md`](docs/verification.md)。

## 当前阶段

当前本地开发分支以实际 `git branch --show-current` 为准。本轮在既有素材面板和时间轴基础上校准了 sourceCrop 的预览/导出共享路径；远程真实媒体仍因无头 Chromium 缺少可用浏览器能力而未验收，请在本地 Chrome/Edge 验证实际预览和 MP4。
